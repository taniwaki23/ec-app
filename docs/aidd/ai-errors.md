目的: 「AIはどこで間違えやすいか」を自分のデータとして貯め、レビュー観点チェックリストに反映する。

| 項目 | 書くこと |

## #001 (2026-09-27) SQL: 「一度もレンタルしていない顧客」を INNER JOIN で書いた

- 依頼: dvdrental で、一度もレンタルしていない顧客を出すSQL
- AIの出力の誤り: `customer INNER JOIN rental ... WHERE r.rental_id IS NULL` と書いた。INNER JOIN は相手のいない行を消すので、結合後に rental_id が NULL の行は存在せず、**どんなデータでも常に0件**になる。dvdrental では正解も0件(全599人がレンタル済み)のため、結果だけ見ると正しく見えた(たまたま正しい)。
- どう気づいたか: 別の方法で件数を確かめた(`COUNT(*) FROM customer` = 599 と `COUNT(DISTINCT customer_id) FROM rental` = 599 を比較)。
- チェックリストへの反映: 「〜していないもの」を探すSQLでは、INNER ではなく LEFT JOIN(または NOT EXISTS)になっているかを確かめる。

## #002 (2026-09-27) 説明: ポートを公開しない案の欠点を誤って説明した

- 依頼: compose で DB のポートを公開しない案(B案)のメリット・デメリット
- AIの出力の誤り: 「Windows から直接 SQL を試せない」と説明した。実際には `docker compose exec db psql` でコンテナ内から試せる。できなくなるのは Windows 上のツール(GUIツール等)からの接続だけ。
- どう気づいたか: 「ポートを公開しないとは? どういう手順でできるの?」と深掘りの質問をし、AIが手順を説明し直す中で誤りが判明した。
- チェックリストへの反映: AIの説明で、自分が手順を具体的に想像できない部分は「どういう手順で?」と深掘りの質問をして確かめる。
