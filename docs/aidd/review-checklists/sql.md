# SQL レビュー観点チェックリスト v0.2

- 作成日: 2026-09-28(v0.2: 同日のSQL検証5本の結果を反映)
- 用途: AI が書いた SQL をレビューするときに上から順に確認する。
- 育て方: `docs/aidd/ai-errors.md` に新しい誤りを記録したら、ここに観点を追加・修正する。

## 最初に確認

0. **要件を満たしているか**
   - 依頼の言葉(「〜ごとに」「前月と比べて」「最も」「過去1か月」)に対応する部品が SQL の中にあるか。見つからなければ要件漏れ。
   - 曖昧な言葉(「少ない」「トレンド」「店舗別」)の定義を、書かせる前に決めたか。
   - 実例: 2026-09-28 ②(前月比を頼んだのに1か月分を数えるだけだった)。

## 最重要(被害が大きい・気づきにくい)

1. **トランザクションの範囲は正しいか**
   - 一緒に成功/失敗すべき更新(例: 注文登録と在庫の減算)が同じトランザクションに入っているか。
   - 同時に実行されたとき(最後の在庫1個を2人が取り合う)に在庫がマイナスにならないか(`SELECT ... FOR UPDATE` か、条件付き UPDATE `WHERE stock >= :qty` か)。
   - 被害: データが壊れる(在庫マイナス、二重請求)。
2. **JOIN した後の集計で、同じ行が重複して数えられていないか**
   - 1対多の表(例: film_actor、order_items)を JOIN したまま SUM / COUNT していないか。
   - 対策: 先に集計してから JOIN する、または `COUNT(DISTINCT ...)` を使う。
   - 要件に不要な表を JOIN していないか(例: カテゴリ別売上に film_actor)。
   - 検算: 分類ごとの合計を足して、元の合計を超えていないか。
   - 被害: エラーなしで間違った数字が出る(売上の水増し)。
   - 実例: 2026-09-28 ①(film_actor の JOIN で約6倍、順位も入れ替わった)。
3. **N+1 になっていないか**
   - 一覧を取った後、1件ずつループで追加の問い合わせをしていないか(発行クエリ数を確認)。
   - 被害: 画面が遅くなり、データ量に比例して悪化する。

## 行が消えていないか

4. **INNER と LEFT の選択が要件に合っているか**
   - 「〜していないもの」「相手がいなくても表示したいもの」は LEFT JOIN(または NOT EXISTS)。
   - `JOIN` とだけ書いてあったら INNER JOIN と読み替え、「相手がいない行が消えてもよいか」を確認する。消えても結果に影響しない場合もある(例: 在庫のない映画には売上がない)。
   - 実例: ai-errors #001(INNER JOIN で未レンタル顧客を探して常に0件)、2026-09-28 ③(在庫0の映画42本が消えた)。
5. **LEFT JOIN の相手の表の条件を WHERE に書いていないか**
   - WHERE に書くと NULL の行が消え、実質 INNER JOIN になる。相手の表の条件は ON に書く。

## 値と単位

6. **NULL の比較が正しいか**
   - `= NULL` ではなく `IS NULL`。
   - `NOT IN (サブクエリ)` のサブクエリに NULL が1件でも混ざると結果が0件になる → `NOT EXISTS` を使う。
   - LEFT JOIN の後は `COUNT(*)` ではなく `COUNT(相手の列)` で数える(`COUNT(*)` は NULL の行も1と数え、0件が1件になる)。
7. **GROUP BY の単位が、求めている単位と合っているか**
   - 「顧客ごと」なのに名前だけで GROUP BY していないか(同姓同名がまとまる)。キーでまとめる。

## 検証

8. **件数を別の方法で検算したか**
   - 結果が0件・少なすぎる・多すぎるときは特に疑う。正解が0件にならないテストデータでも試す。
   - 日付条件は、データの実際の期間と合っているか(`CURRENT_DATE` 基準で0件にならないか)。データの空白期間や途中までの月がないかも見る。

## 性能

9. **インデックスが効かない書き方になっていないか**
   - 列を関数や計算で囲んでいないか(例: `WHERE DATE(ordered_at) = ...`)。先頭が `%` の LIKE。
   - 実行計画(EXPLAIN)で Seq Scan になっていないか確認する。
10. **全件を取得していないか**
    - 一覧取得に LIMIT / ページングがあるか。`SELECT *` で不要な列まで取っていないか。
