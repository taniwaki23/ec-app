# 非機能要件(NFR)

- 作成日: 2026-09-27
- 対象: ec-app(小規模ECの受発注・在庫管理システム)
- 前提: 学習用。AWSリソースはすべて Terraform で管理する。

## 1. 可用性

| 環境 | 目標 | 構成への影響 |
|---|---|---|
| 学習環境 | 目標なし(いつ止まってもよい) | 単一AZ。作業日だけ `apply` し、同じ日に `destroy` する |
| 本番(想定) | 99.9%(年間約8.8時間までの停止を許容) | DBをマルチAZにするかは費用とのトレードオフとして ADR で決める |

- 理由: 小規模ECのため利用者が少なく、停止による機会損失が小さい。一般的なWebサービスの水準は確保しつつ、費用を最優先する。
- 代償: 年間で最大約8.8時間の停止を受け入れる。障害・保守の時間帯は注文を受けられないことがある。
- 検討して捨てた水準: 99.9999%(年間約32秒)— 小規模ECの損失に対して、複数リージョン構成などの費用・運用負荷が見合わない。

## 2. コスト

| 項目 | 金額(USD/月) |
|---|---|
| 月の予算(AWS Budgets 設定済み) | 10 |
| 固定費(S3の state、ECR など。10/01 に公式料金で確認) | 約1(仮置き) |
| 予備(消し忘れ・想定外の課金に備える) | 2 |
| 作業日の変動費 | 7 |

- 1作業日の上限: 約0.47 USD(月15日の稼働を想定)
- 運用: 作業日だけ `apply` し、その日のうちに `destroy`。NAT Gateway は常設しない。毎週土曜に Cost Explorer で実費を確認する。
- 理由: 学習の初期は消し忘れや想定外の課金が起きやすいため、1回のミスで予算を超えないよう予備を持つ。

## 3. セキュリティ

1. 秘密情報を公開しない。`.env`・`*.tfvars`・`*.tfstate` は Git に登録せず、秘密の値のやりとりは AWS Secrets Manager を使う。
2. DB はインターネットに公開しない。プライベートサブネットに置き、アプリのサーバー(のセキュリティグループ)からの接続だけを許可する。
3. 権限は最小権限の原則で付与する。ルートユーザーは日常の作業に使わず MFA を設定する。CI(GitHub Actions)には長期のアクセスキーを渡さず、OIDC で一時的な権限を渡す。
4. 保存データ(RDS のストレージ・バックアップ、state を置く S3)を暗号化する。
5. ログに個人情報や秘密情報を出さない。

- 補足: ローカル開発環境の DB ポート公開(5433)は学習用の例外であり、AWS上の構成には適用しない(ADR docker-001 参照)。
